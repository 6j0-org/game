# Game: notes for agents

- The game is "Game". Storage keys (localStorage and the server's JSON files) start `game:`.
- Plain ES modules, no bundler. Three.js comes only from the import map in `index.html`.
- Game logic modules (`blocks`, `noise`, `biomes`, `townplan`, `commands`, `world`, `mesher`, `body`, `player`, `mobs`, `fireballs`, `items`, `daycycle`, `spells`, `drones`, `phantoms`, `settings`, `game`) must stay free of Three.js and DOM access (except `Player.attach`), so they run in Node: the multiplayer server imports them.
- Players (accounts): `accounts.js` (logic: `Accounts` in the world store under `game:accounts`; uid, name, SHA-256 of the key, admin, banned, recovery code). Before joining, a connection sends `create` { name } / `recover` { code } (answered `created` { uid, key, name } or `denied`), then `hello` { uid, key } (`game.authenticate`, then `game.join(uid, send)`; refused: `denied` with `login: true`). net.js `openLink()` gives a link (`request`, `join`) for both the server and single player; account.js `signIn` keeps the key in localStorage per server address (`player-key:<host>` or `:single`) and shows Create/Recover Player on the title screen. Saves are per uid (`loadPlayer(uid)`, `savePlayer(uid, null)` deletes). The first Player is Admin; `admin` { op } messages (list, recover, rename, kick, ban, adminRole, delete) are `game._admin`, answered with `players` / `adminNote`; Settings > Players (main.js `renderPlayers`) shows them. Names are unique (`rename` answers `renamed`).
- Client/server split: `game.js` is the only authority (world edits, mobs, drops, projectiles, health, inventories, time). `main.js` never simulates those; it sends action messages (`place`, `break`, `attack`, `cast`, `throw`, `eat`, `washed`, `print`, `phone`, `state`) and draws what `snap`/`blocks`/`you`/`fx`/`msg` say. Single player runs the same `Game` in the browser via `net.js`, so there is one code path. New gameplay goes in `game.js` (plus a message), not in `main.js`.
- Mobs, drops and projectiles take a list of players; anything that targets "the player" must pick one (usually the nearest living one).
- The server (`server/`) uses only Node built-ins. Don't add npm dependencies without asking.
- Rendering lives in `main`, `avatars`, `effects`, `mobModels`, `sky` and `textures`. Logic returns event lists; `game.js` turns them into messages and `main.js` into effects.
- Lighting: `daylight()` is perceived brightness. Multiply materials by `lightMultiplier(light)` (gamma 2.2), not by the raw value.
- Models face -Z. Yaw follows the camera convention: forward = (-sin yaw, -cos yaw).
- Coordinates: +Y is up. Chunks are `CS`×`CH`×`CS` (16×80×16). The local index is `(y*CS + z)*CS + x`. Chunk coordinates are `x >> 4`, `z >> 4`.
- `player.pos` is at the feet. Eye height is `EYE_HEIGHT`. The body is 0.6 wide and 1.8 tall.
- Adding a block: add an ID and a `BLOCKS` entry in `blocks.js`, paint its tile(s) in `textures.js`, bump `TILE_COUNT`, and set its `SEE_THROUGH`/`SOLID` flags.
- Shaped blocks (stairs, slabs, doors) are one id per variant (facing/open/top) with boxes in `SHAPES`; `body.js` collides with those boxes and steps up 0.55, `mesher.js` draws them. The inventory item is the family's `baseId`; `orientedId(id, facingOf(yaw))` picks the variant when placing. Doors are two blocks; `game.js` places, toggles (`use` message) and breaks both halves. Beds are two blocks too: `BED`+facing is the head (pillow), `BED_FOOT`+facing the foot; you place the foot (sending the head id) and the head goes one block further in the facing; `bedOther` finds the other half.
- Fences are one id whose boxes depend on neighbours: always go through `shapeBoxes(id, at, x, y, z, collision)` (not `SHAPES` directly); their collision is `FENCE_HEIGHT` (1.5) tall, so `body.js` also checks the layer below the body. Trapdoors toggle via `use` like doors. Ladders are non-solid; `Body.onLadder` drives climbing in `step`, and the game ignores falls on ladders.
- Lava lamps aren't meshed: the mesher returns their positions, `lamps.js` draws them, and `setLamps` (flashlight shader) lights the nearest `LAMP_MAX`. Hostiles spawn only when daylight < `DARK` and never within `LAMP_SAFE` (a sphere) of a lamp (`mobs.js` `_nearLamp`).
- Magic (`spells.js`): all numbers are settings (group Magic; defaults in `MAGIC_DEFAULTS`): read them with `magic(settings, key)`, `spellCost`, `spellCooldown`, `potency`, `sizeScale`/`sizeSpeed`, `maxMana(stats, settings)`, `manaRegen(stats, settings)`, never as constants. Mana (`player.mana`, max/regen from Big Brain via `maxMana`/`manaRegen`) is owned by the game and sent in `you`. Players know only the spells they've learned (`player.spells`, saved, in `you`; Buildy Bois know all): reading a scroll of an unknown spell teaches it (`_cast` learns and spends it instead of casting); casting an unknown spell is refused. The client picks a spell with the wheel (`spellList()`: 'none' then the known ones in `SPELL_ORDER` order; `currentSpell()`) and sends `cast` when an empty/Wand/Staff hand clicks (`isFocus`; `FOCUS` is the potency). `game.js` `_cast` does every spell: fireballs/missiles/icebolts are fireball kinds (missiles home in `_steerMissiles`; icebolts hit directly and freeze water with `_freeze`), blizzards are thrown as a 'snowball' fireball kind carrying `fb.storm`, and become `game.storms` where it lands (`_blizzard(fb, at)`, bitten in `_updateStorms`, sent as `snap.storms`), both chill (`_chill`: mobs `chillT`, players `effects.chill`, speed × the Chilled speed setting), lightning `_chainLightning`, shrink/enlarge/polymorph/hallucinate `_hex`. Shrink and Enlarge are the size spells (`SIZE_SPELLS`: one shared path; a target has at most one, a new one replaces the old): mobs have `sizeSpell`/`sizeT`, players `effects.shrink`/`effects.enlarge` (`Player.sizeSpell`); bodies grow only as far as there's room (`Body.fitScale`; the player's actual size is `bodyScale`). Mobs also have `polyT` and `halluT` (hallucinating: ignores players, flails about); players `effects.polymorph` and `effects.hallucinate` (the client draws harmless phantom mobs from `phantoms.js`, negative ids, never sent to the game), stoneskin sets `effects.stoneskin` + `player.armor` (used by `Player.damage`), flight `effects.flight` (the game accepts `flying` from Buildy Bois or while it lasts; F toggles it), teleport `_blink` (raycast, then `_teleport`), Dragon's Breath `_breath` (a cone, line of sight; fx 'breath'), blind `_hex(...'blind')` (players `effects.blind`: the client blurs the canvas by `blindBlur`; mobs `blindT`: they can't see anyone), invisibility `effects.invisible` (mobs ignore you; avatars hide). Attacking ends invisibility (`_reveal`). Polymorphed players can't act (the message gate) or move (`speedMul` 0); `sizeScale` scales bodies, eyes and `_mult` (damage); speed follows `sizeSpeed` (shrunk: the size; enlarged: the Enlarged speed setting). Snapshots carry `invisible`/`poly`/`scale`/`stone` (players) and `poly`/`scale` (mobs); `showInfant` swaps in the infant model.
- Two-handed melee weapons have an attack per button (`TOOLS[k].attacks`, read with `meleeStyle(kind, hand)`): 'sweep' (client sends `attack` { hand, o, d }; `game._sweep` hits every target in `sweepArc` within `sweepReach` for `sweepDamage` %) and 'chop' (an ordinary targeted `attack`, `chopDamage` % and `chopCooldown` × the cooldown). avatars.js animates them from the left/right swing timers.
- Guns (`weapons.js`) fire via the `fire` message; `game.js` checks ammo/cooldown and does hitscan, rail and projectiles (rockets/orbs are fireball kinds). Ammo crates and Power Surge orbs are drops. Headshots: `_isHead(target, y)` (top `headshotZone` % of the body) multiplies hitscan pellets, rail hits and arrows by `headshotDamage`; `_headshot(id)` sends the shooter `headshot`, and main.js plays the `headshot` sting plus `sound.announce('HEADSHOT!')` (speech synthesis, the only non-synthesised voice). The grapple target is client-side physics sent in `state`.
- Every gameplay number is a Server setting (the user's rule). Mechanism (`tuning.js`): modules register numbers with `tune(group, { key: [default, name, desc, { min, max, step, unit }] })`, or turn table fields into live settings with `bindTunable(obj, field, group, key, name, desc)`, and read the live value as `T.key` at run time (never copy it into a module-level const). `settings.js` imports every registering module and exposes `SETTINGS` (= `TUNABLES`), `SETTING_GROUPS` and validation; `game.settings` and the client's `settings` are the same `T` object (`setTuning`). New features must register their numbers the same way. Not settings: network/engine plumbing (protocol, snapshot/save rates, reach checks), terrain-generation constants (`world.js`, `biomes.js`: changing them would change existing worlds), body sizes, and purely visual/audio constants.
- Changing a setting's default: saves keep every value, so add [version, key, old default] to `CHANGED_DEFAULTS` in settings.js and bump `SETTINGS_VERSION`; `game.js` runs `migrateSettings` once per world. Renaming a setting: add [version, old key, new key] to `RENAMED_SETTINGS` (same bump).
- Server settings (`settings.js` `SETTINGS`): `game.settings`, changed by anyone with the `setting` message, saved as `game:settings`, sent in `welcome` and broadcast as `settings`. Gun damage/rate/pellets/spread go through `gunStats(kind, settings)` (never read `GUNS[kind].damage/cooldown` directly when firing). The client keeps its copy in `settings` (main.js) and draws the panel from `SETTINGS`, as the Server tab of Settings (`#client` section `server`; `settingsPanel.shown()` on opening it; the main menu's Server settings button is `openClient('server')`).
- Terrain generation must stay deterministic for a given seed. Saved edits are keyed by seed and stored as chunk-local indices.
- Generations: `biomeAtV1` (biomes.js) is the original, 10× smaller biome map; never change it. When a world first loads after the change, `World._loadGen` freezes every chunk with edits (plus one around each) as a legacy chunk, saved as `game:gen:<seed>` and sent to clients in `welcome.legacy` (`world.setLegacy`, before generating anything). Legacy chunks generate exactly as before; `blendAt` eases heights over `BLEND` blocks around them, and no zone buildings stand in that ring. Always go through `world.biomeAt`/`heightAt`, not the biomes.js functions directly. There are three generations now: V1 (`biomeAtV1`, `world.legacy`), V2 (`biomeAtV2`, with the Ball Pit; `world.gen2`, frozen when a world first loads with V3: every edited chunk plus a ring, saved in the gen record `{ v: 3, legacy, gen2 }` and sent as `welcome.gen2`) and V3 (`biomeAt`: V2 with the ball pit band as `cyber`). Inside World use `this._biomeNew` (V2/V3) or `this.biomeAt`, never the imports. Changing generation again means another frozen generation, not editing the current one in place.
- Fantasy Town (`townplan.js`): a special zone; buildings are designed in a local frame (door on the +lz wall) and rotated with `rot`, facings with `(f + rot) % 4`. Plots and markets are built only if all their corners are `core` (deep in the zone, outside the blend ring). Shops: one unbreakable counter block per shop (`SHOP_COUNTER`+i, `SHOP_ORDER`, `UNBREAKABLE`); right-clicking opens a `TileShop`, and the game's `buy` message checks the counter is in reach and the item is in that shop's `SHOPS[shop].wares` (`townOffer`). Town-only items have `town` (TOOLS, FOOD, GUNS, AMMO): `printable`, `shopOffer` and the CONSUME/printer lists exclude them. Armor: TOOLS with `armor` (%) and `speed` (%), worn with the `wear` message (`player.worn`, not counted in `tools` while worn; `{ kind: 'none' }` takes it off). Worn armor shows on avatars (`snap.players[].worn`; looks in `ARMOR_LOOKS`, avatars.js `dressArmor`; a new armor needs a look there). Scrolls: `scroll:<spell>` in `player.scrolls`; `cast` with a scroll in hand is free, uses one up and casts at `scrollPotency`. Bows are GUNS of type `arrow` (a fireball kind with gravity, direct hit). Bows with `draw` (seconds, a setting) are held to draw and fire on release (main.js `bowDraw`; `fire` carries `draw` 0-1, which scales speed and damage; under `bowMinDraw` nothing fires; `state.draw` -> `snap.players[].draw` for the avatar pose). Spent arrows (`_spentArrow`): `arrowBreak` % break; otherwise a mob keeps `arrows` (drawn in mobModels, dropped as 'arrow' loot on death), a player hit drops one at their feet, and a block hit leaves an 'arrow' drop with `dir` (stuck, no physics until someone comes near). Picking up an 'arrow' drop adds 1 to `ammo.arrows`.
- Keep the art original: procedural tiles and our own palette and UI. Don't copy assets or the look of existing games.
- Selection is per hand: `player.hands.left/right` hold an item "kind" ('empty', 'phone', a tool/food/dish name, or `block:<id>`; the Wand and Staff are the tools 'wand' and 'staff', owned like any other). The left mouse button uses the left hand and the right button the right hand. Two-handed items (`twoHanded` guns, `isTwoHanded`) sit in both hands at once; `Player.hold`/`validateHands` keep that consistent. Guns fire with their hand's button (two-handed: left). A gun with `scope` (the Sniper Rifle) doesn't aim on hold: each right-click steps `scopeLevel` (main.js) through the `scopeZoom1-3` settings and off; scoped, `aim` is sent and spread uses `scopeSpread`, the `#scope` overlay shows, and your own avatar is hidden in first person. Zoom is `zoomMag` (eased in log steps) for both ADS and scopes. The right button aims down sights instead of using the right hand only when `canAim()` (main.js): a two-handed gun, or a gun in the left hand with the right hand empty (`adsT`: magnification `1 + adsZoom%` turned into an FOV, `player.lookScale` = 1 / magnification, `aim` flag on `fire` tightens spread by `adsSpread`). Except: right-clicking an interactive block (door, trapdoor, bed, Cold Wallet, printer) always uses the block instead of the right-hand item (`interact()` in `main.js`). `inventoryList`, `filterItems` and `tabComplete` in `items.js` drive the Q/E picker (`picker.js`), opened by a tap of Q/E (on keyup). Hotbars: `player.hotbars` { left, right: 8 kinds or null } (saved, in `you`, set with the `hotbar` message); main.js `hotbarHold` (Q/E held) makes the wheel `stepHotbar` instead of picking spells; picker tiles are draggable onto `.hotbar .slot`s (drop sets, slot-to-slot swaps, dragging off clears).
- Console: `/` opens it in main.js (a menu for `menuOpen()`, but it keeps the pointer lock and doesn't pause). It sends `command` { text } (allowed while dead or on the phone, like `setting`); `game._command` runs `runCommand` (commands.js) and replies with `console` { text, error? } messages. Add commands to `COMMANDS` (usage, desc, aliases) and handle them in `runCommand`; anything that changes the world or a player goes through game methods. Teleports use `game._teleport(entry, pos, note)`, which sends `teleport` { pos } (the client moves itself) and sets `teleportT` so stale `state` positions aren't judged as a fall. `/teleport town` uses `world.findMarket`; `world.surfaceAt` gives a standing height. `/give` uses `findItem`/`giveItem`/`giveDefault` (items.js: `allItems()` lists every kind with a typeable `word`), `/summon` uses `findMob` and spawns through `game.mobs.spawn`; both are behind the `cheats` setting. Item kinds must be unique across TOOLS, FOOD and DISHES (a kind names one item everywhere: drops, hands, icons, models).
- Sound: all effects are synthesised in `audio.js` (`SOUNDS` map, no audio files). The client triggers them from its own actions and from game messages and snapshot changes; the game sends no sound events.
- Lit materials: anything a flashlight should light must be wrapped in `withFlashlight()` (`flashlight.js`).
- Phone: an item kind ('phone', always owned; new players start with nothing else); clicking with it opens the phone UI (a menu: frees the mouse, blocks game input, but never pauses or speeds up the world). It's just CONSUME now (`PhoneApps`: `render`, `tick`, which runs in single player too). Single player keeps simulating while the phone is out (`pausingMenu` in the frame loop excludes it). Chat is the console: T opens it empty, / with a slash; plain text is sent as `text` { to: 'all' } (game.js `_text` relays it; the client shows it with `popup`), `/msg` (commands.js) sends `text` to one player. There are no phone calls and no phone map.
- Voice: everyone in multiplayer is in one channel. `voiceroom.js` (game side) keeps the members and relays set-up (`voice` messages: `join` after the browser asked for the mic, `signal`; out: `room`, `signal`); `voice.js` (client) is a WebRTC mesh where the later joiner of each pair offers. Each remote stream goes source -> `pitch-shift` AudioWorklet (`pitchshift.worklet.js`, ratio `voicePitch(scale)` from `snap.players[].scale`) -> gain -> destination, with a muted `<audio>` element keeping Chrome's stream alive. `voice.update` (every frame, throttled) sets gain/ratio `.value`s: master × per-player volume × `nearbyVolume(dist)` if that player is "nearby only" (`voiceNear`/`voiceRange` settings). Per-player prefs are client-side, by name, in localStorage. The V menu is a menu (`voiceOpen`) that frees the mouse and doesn't pause. Microphones need a secure context (https or localhost). `window.game.voice` and `.sound` are there for debugging. Only "nearby only" voices are positional: they're routed gain -> panner (direction only, rolloff 0; distance is our `nearbyVolume`) -> `acoustics.input`; others go gain -> destination (`Voice._route`). Walls muffle nearby voices via `voice.occlusion` (a low-pass and a volume factor from `muffle`). Whisper/shout: holding Z/X sets `voiceMode` (main.js), sent in `state` as `voice` and in snapshots as `players[].voice`; listeners scale `voiceNear`/`voiceRange` by `voiceReach` (`voiceWhisper`/`voiceShout` settings). Avatars show a talking icon from `p.talking` (set from `voice.talking(id)`).
- Acoustics (`acoustics.js`): `blocksBetween` (walls along a line), `probeSpace` (rays from your head: open/room/hall/cave/canyon, plus underwater and Hell, every 0.5 s in `updateAcoustics`), and `Acoustics` (generated impulse responses; `set` a state, `tick` eases gains). Game sounds: world sounds go `master` -> acoustics -> compressor; `UI_SOUNDS` go `uiBus` straight to the compressor. Positional one-shots get a low-pass from `sound.occlusion`. `sound.track(list)` keeps continuous `MOVERS` sounds (projectiles, drones) with Doppler (pitch from closing speed vs `SOUND_SPEED`); call it every frame with everything that should be humming. HRTF (`sound.setHrtf`/`voice.setHrtf`, saved as `game:3d-sound` only when the player clicks it, on unless that's '0') switches every panner's model. Sound names in `SOUNDS` must be unique (a duplicate key silently replaces the earlier one).
- Money: tool prices are in dollars (`TOOLS[k].usd`); the game owns the ZEC/USD `rate` (`market.js`, sent in `welcome`/`snap`) and charges `zecFor(usd, rate)` at print time. CONSUME (phone shop): `order` message; `shopOffer`/`shopCatalog`/`grantItem` in items.js cover every item (ammo kinds are `ammo:<type>`); the game adds the delivery fee setting, keeps `player.orders` (saved, sent in `you`) and, when one is due, launches a drone (`drones.js`, in `snap.drones`, drawn with `buildDroneModel`) that hands it over in `_droneArrived`. `order` (and `setting`) are allowed while the phone is out or you're dead. The printer and CONSUME both draw with `TileShop` (tileshop.js), the picker's tile look. Wallets are fractional ZEC (2 decimals).
- Money: `player.wallet.zcash` is carried; `wallet.cold` is cold storage (Cold Wallet block, `vault` message) and survives death.
- Death drops a backpack (`game._dropBackpack`: every inventory, worn armor and carried ZEC into `game.backpacks` { owner uid, x, y, z, t, items }, saved as `game:backpacks`); only the owner picks it up by walking into it (`_backpacks`), and it expires after `backpackMinutes`. Sent as `snap.backpacks` (the owner sees a beam). New inventories must be added to `_dropBackpack`. Coins are worth `coinValue()` (0.01–1.00).
- Beds: `player.bed` (set with the `bed` message, saved, sent in `you`); `game._spawnPoint` respawns you there if it's still a bed with room above. The Tab map draws it.
- After an action from a menu (printer, vault), call `game._sendYou(e)`: single player pauses while menus are open, so the tick won't send it.
- Blocks are limited: `player.blocks` (id -> count) fills when you break blocks and empties when you place them; `BLOCK_PRINTS` (items.js) are printable. Buildy Boi mode (`player.buildy`, `buildy` message, 10 s `BUILDY_SWITCH`) gives `itemCount` = Infinity for every block, tool, food, scroll and ammo kind (`buildyHas`; not dishes or unfired pottery), uses nothing up (always consume through `spend(player, inv, key, n)` and check ammo with `ammoCount`; armor worn as a Buildy Boi is `wornFree` and goes when the hat comes off), allows flying (the game only accepts `flying` from Buildy Bois), makes `Player.damage` a no-op (invincible), makes mobs ignore the player (`ignored()` in `mobs.js`). Avatars show a hard hat from `snap.players[].buildy`.
- The Tab and phone maps leave out invisible players (`mapArgs`).
- Death messages: `Player.damage(amount, x, z, knock, source)` remembers `source` as `lastHit` (`{ cause: 'mob', mob }`, `{ cause: 'player', by, byId, weapon }` from `game._src(id, weapon)` or `_shotBy(fireball)`, `{ cause: 'fall', blocks }`, `'lava'`, `'lactose'`, `'allergy'`, `'void'`). When a player dies the tick broadcasts `_deathText(e)` (kind 'death') once (`deathTold`). New ways to hurt players must pass a source; `Mobs.blast` and `_detonate` take one too. Joins, leaves, renames (kind 'join') and level-ups (kind 'event') are broadcast in multiplayer.
- Gardening (`garden.js`): tilled dirt is `SOIL` + wet*8 + weeds (0 none, 1-4 = weed levels 0-3, 5-7 = level 3 in older saves; weeds never kill crops: `harvest(id, rand, soil)` cuts a ripe plant's yield by `weedHarvestCut` when its soil's weeds are fully grown), crops are `CROP` + crop*4 + stage (stage 0 = the seed item, via `baseId`, in HOTBAR). All state is in block ids (saved as edits). `game._garden` handles the `garden` message (Tiller `till`, Sprayer `water`, Weed Torch `torch`); `_newDay` runs `newDay` (every soil block in `world.edits`) when `game.time` wraps past sunrise (also from `/skip`). Seeds only go on soil (`canPlant`, checked in `_place`); `_harvest` drops produce (FOOD entries named like `CROPS`). Numbers are settings in group Gardening.
- Your own body (`selfAvatar`, an Avatars instance): every view draws it, holding items as everyone else sees them (`holdPose` in avatars.js). Arms have elbows (`a.arms` = upper arms at the shoulder, `a.elbows` = forearms with the hand and the `hold` group); guns and bows (`aim` poses) are held low with the elbows bent and follow `pitch`, so your own arms stay out of your first-person view, and `hold` is counter-rotated so the item points along your view. First person puts the camera just in front of the face (`placeViewCamera`) and hides the head; the old first-person hand models (`handViews`) are no longer shown. Swings (`swing()` bumps `mySwings`) and the mining hand go in `state` (`sw`, `mine`) and snapshots, so avatars animate them for everyone.
- Skills (`skills.js`): `player.skills` (kind -> points; kinds are item kinds, plus 'empty' = Punch, 'magic', 'dishwash', 'plant' = planting a seed in `_place`), saved and sent in `you`. `Player.gainSkill` recomputes `level` (`levelFor(totalPoints)`, thresholds from the levelFirst/levelMore settings) and `maxHp` (`maxHpFor`). `game._skill(e, kind, n)` is the one way to add points (messages, level-ups). Kills: damage sources carry `skill` (`_src(id, weapon, skill)`, fireballs' `skill`, storms' `skill`, `e.castSkill` for spells); mobs remember `lastHit` and their death event's `by` credits it. Tools: `_break` credits the held tool matching `MINE_TOOL`; `_garden` credits the garden tool (Tiller, Sprayer, Weed Torch) when it changed something. Title = best skill's name + "er", or the name itself if it already ends in "er" (`title`). There is no XP any more.
- Character sheet (I): a menu (`sheetOpen`, `setSheet`) down the left half; while it's open `placeViewCamera` shows you from the front (`sheetOrbit` from dragging) and `camera.setViewOffset` frames you in the right half. `body.sheet-open` hides the HUD it would cover.
- `Picker.open(hand, items, current, opts)` takes `{ title, key, hint, placeholder, onPick, onCancel, stay }` to reuse the inventory panel (the /give panel uses it).
- Font sizes in index.html's CSS are all `calc(<px> * var(--fs))` (the Font size client setting, `prefs.fontScale`, default 1.25); write new ones the same way. The title logo is the exception (it's a graphic).
- UI that refreshes on a timer must never replace or rewrite a button unless something changed (a button replaced between mousedown and mouseup doesn't get the click): keep buttons out of redrawn areas, compare before writing (see TileShop.refresh, renderSheet, updateVoiceMenu).
- Clicking outside a pop-up closes it: `POPUPS` in main.js ([isOpen, box element, close]); add new mouse-freeing menus there.
- Notifications: `popup(text, kind)` (main.js) adds a line to the message log (`#chat`, bottom right; `kind` is a CSS colour class, repeats count up). Game `msg` messages, phone texts (`PhoneApps` `notify`) and console replies all go there. Nothing floats mid-screen any more.
- Client Settings (Esc): `#client`, tabs controls/sound/voice/display/graphics/server, plus players for Admins. Client-only preferences live in `prefs` (`CLIENT_DEFAULTS`, saved as `game:client`); `setPref(key, value)` saves and `applyPref` puts one into effect (sensitivity/invertY on the player, `BASE_FOV`, `renderDistance`, `resScale` in `fitRenderer`, echo on both acoustics chains, ambient, info, chat). These are presentation, not gameplay, so they aren't Server settings. Esc: losing the mouse in the game opens the main menu (`openMainMenu`, the `#overlay` title card). One capture-phase Esc router handles menus: Settings goes back to where it came from (`clientFrom`: 'menu' or 'game' for V), the main menu goes back to the game. In-game menus closed with Esc, and `pointerlockerror`, call `showPause()`, which shows the click-to-resume prompt (`#resume`), because browsers only re-grab the mouse on a click. `KEYS` in main.js is the shortcut list: add new keys there. The V key opens the Voice tab.
- Snapshot player fields only reach avatars if `main.js` copies them in its `syncMap(remote.players…)` update: add new ones there.
- Birds (`flies` in MOB_TYPES; species differ by `flock`, `cruise`, `perch`, `thief` and their colours in `BIRDS` in mobModels.js) skip walking physics: `Mobs._fly`. Walking mobs swim in any fluid: `Mobs._waterSurface` floats them `FLOAT_DEPTH` of their height under the surface at `SWIM_SPEED` (or `MOB_TYPES[type].swim`), and a wall while swimming is a shore to climb. Every mob type needs a `BESTIARY` entry (bestiary.js); a test checks this. The Backrooms: `world.backroomsDark(x, z)` (third generation only: clusters of rooms with no light panel); `habitat: 'backrooms'` mobs (clerk, mildew) spawn only there, inside on the floor, day or night (`Mobs._trySpawnBackrooms`), and nothing spawns on the Backrooms roof. Spawning respects habitats: MOB_TYPES `habitat: 'cold'` (penguins) only spawn where `Mobs._cold` (taiga, snow, ice), and seagull flocks only where `_nearWater` (12 blocks). Eating a `flap` food sets `effects.flap`; the player's update turns fresh jump presses in mid-air into flaps.
- Health never regenerates; only eating, respawning and the fall-healing trait (`game.js` `_trackFall`, from `state` positions) restore it. Fall damage (`fallDamageFor`, scaled by the `fallDamage` setting) is also judged in `_trackFall`; fall-healing and gravity-resistant (`lowGravity`) players don't take it. `lowGravity` halves gravity through `Body.gravityMul`, which main.js sets from the traits in `you` (the client simulates its own player).
- Traits & effects: `player.traits` (gluten/lactose) are rolled by `game.js` at every spawn (`rollTraits`); foods with an `allergen` don't heal intolerant players and trigger `player.effects` (headache, upset) instead. The game owns effects and sends them in `you`; the client draws them and applies `player.speedMul` to movement.
- Block gravity (`gravity.js`, `game.gravity`): every block falls unless it's joined to the floor (y = 0) through touching non-fluid blocks. Only blocks next to a change are checked (`World.onChange` -> `changed`), so untouched terrain never moves. An unsupported structure falls as one rigid group (`_step`, one block at a time, accelerating), sinks through fluids (`_fill` lets them close in behind), lands on anything solid, and is held up by bodies in the way (which take `crushDamage`, source `{ cause: 'crushed' }`). Ice on water floats. Its moves go out as `blocks` with `quiet: true` (no break/place sounds); landings are the `blockLand` fx. Settings: group Blocks (`blockGravity`, `blockFallAccel`, `blockFallSpeed`, `blockFallLimit`, `crushDamage`). Structures bigger than `blockFallLimit` count as grounded.
- Crafting (`crafting.js`): `CRAFTS` { id, out ('block:<id>', a MATERIALS key or a TOOLS key), n, needs: { materials, blocks } }; R opens the panel (main.js `openCrafting`), which sends `craft` { id }; `game._craft` checks `canCraft`, `spend`s and `grantCraft`s. `player.materials` (MATERIALS in items.js: sticks, fiber, cord, stone heads) is an inventory like the others (saved, `you`, backpacks, `itemGroup` for drops). Leaves drop 'stick' and grass 'fiber' drops in `_break` (stickChance, fiberChance). Stone tools (`crafted: true`, not printable/sold) mine via `STONE_TOOLS`/`rightTool` (blocks.js) at `stoneToolSpeed`.
- Cooking (`cooking.js`): `STATIONS` (range, campfire, press: blocks RANGE/CAMPFIRE/OLIVE_PRESS, `stationOf(id)`), `RECIPES` { out, n, needs, at, time } (raw->cooked ones generated from FOOD `cookedFrom`). Right-click a station: main.js `openKitchen` (TileShop) sends `cook` { out, x, y, z }; `game._cook` spends the ingredients (`spend`), runs `player.cooking` { out, n, t } (saved, in `you`), `_cooked` grants it and trains 'cooking'. FOOD flags: `raw` ('meat'|'fish': heals less; raw meat may set `effects.upset` with `e.upsetCause` 'rawmeat'), `cookedFrom`, `ingredient` (not edible). A Bucket in the left hand + right-click water sends `fill` (`findWater`, `waterReach`) for a 'water' ingredient. SINK counts as water for `nearWater`. The recipe book (K) is `setRecipes` in main.js; new recipes show up there automatically. Crops past the first 11 use ids from `CROP2` (256); always use `cropId`/`cropInfo`/`cropTile`/`CROP_IDS`. Block ids are 16-bit (`MAX_BLOCK_IDS` flag tables, Uint16Array chunks).
- Fishing (`fishing.js`): the 'rod' tool (`fishing: true`, not a mining kind) sends `fish` { hand, o, d }; `game._fish` casts (`findWater`) or reels in, `_tickFishing` waits (`biteWait`), opens a bite window and reels the line in if you walk off, switch items or the water's gone. The line is `e.fishing` { x, y, z, bx, by, bz, hand, t, bite }, sent as `snap.players[].bobber` and drawn by `updateBobbers` (main.js). Fish are FOOD with `fish: true` (from `FISH`); `rollCatch` picks one (or 'junk': a dirty dish). fx: fishCast, fishBite, fishCatch.
- Pottery (`pottery.js`, blocks.js): clay blocks (`CLAY_BLOCKS`, found by digging via `clayFind` in `_break`), workstations `POTTERY_WHEEL`/`KILN`/`GLAZING_TABLE` (right-click: `openPottery` in main.js, one TileShop panel), and pieces as shaped blocks: `potteryId(obj, clay, glaze, lit)` / `potteryInfo(id)` (ids 157-228; lit luminaries are `LUMINARY_LIT`+, glow, and are pushed to the mesher's `lights` as 'luminary'; `baseId` maps them to the unlit item). The process is throw (wheel) -> trim (wheel) -> bisque fire (kiln) -> glaze (table) -> glaze fire (kiln). Unfired pieces are `player.unfired` (keys 'thrown:<obj>:<clay>', 'trimmed:...', 'glazed:<obj>:<clay>:<glaze>'; `unfiredInfo`, `firedId`, not holdable); bisque pieces and finished glazed pieces are blocks. The `pottery` message { op: throw/trim/fire/glaze, x, y, z, ... } is `game._pottery`; the kiln is `player.kiln` { pieces, t } (saved, sent in `you`; `fireSeconds`: bisque or glaze time), finished by `_kilnDone`. Luminaries toggle through `use`. Block ids are 16-bit now (see Cooking).
- Snow (`SNOW_LAYER`, 229): a thin, non-solid shaped block Icebolts (`_snowAround`) and Blizzard bites (`_snowAt` on random spots) lay on solid full blocks. `game.snow` ("x,y,z" -> seconds) melts it (`_meltSnow`, `snowMelt` setting; snow found in saved edits gets a new timer at start). Placing a block into snow replaces it (both `free` checks). Settings: snowCover, iceboltSnow, blizzardSnow, snowMelt (Magic).
- Townsfolk (`npcs.js`): not mobs. `Npcs` (game.npcs) brings out each market square's people when a player is within `npcRange` of it (`world.findMarket`) and removes them when nobody is: five shopkeepers at `MARKET_SHOPKEEPERS` (townplan.js: behind their counter, `counter` is the counter block) and `npcWanderers` villagers walking between `marketOpenSpot`s. Identity (name, look, `hands`, `worn`, and `key` = "role@ox,oz" / "villager<i>@ox,oz") is a hash of the seed and the market, so it's the same every visit; runtime `id`s are not. They can't be hurt and aren't in `mobs.list`. Sent as `snap.npcs`; the client keeps `remote.npcs` and draws them with a second `Avatars` (`npcAvatars`, name tag prefixed ❗/❔/❓ by `npcMarker`); raycast kind 'npc', and clicking one sends `talk` { id }.
- Quests (`quests.js`): `player.quests` = { active, count (npc key -> done), cool (npc key -> epoch ms), next } (saved, `cleanQuests` on load; `you.quests` = { active, cool: [keys], done }). Kinds: 'fetch' (item kinds from `WANTS[role]`, spent at turn-in), 'lost' (a `lost:<key>` thing at `spot`, found by walking up to it in `_tickQuests`; never an inventory item; drawn client-side from `you`, models in DROP_SHAPES), 'till' (`_tilledFor` from `_garden` counts tilled blocks near `spot`). Offers are deterministic: `questOffer(role, offerSeed(npcKey, token, done))`, and `_lostSpot`/`_tillSpot` use the same seeded `rand`. `_talk` answers with an `npc` message (text, `offer` or `active`/`ready`, `counter`); `quest` { op: accept/turnin/abandon } is `_quest`. Rewards are dollars (`WORTH`, settings) paid as `zecFor` at turn-in, plus 'quest' skill points. Buildy Bois can't take or finish quests. Finds for quests come from `forage.js` (`forageFind` in `_break`, into `player.materials`; MATERIALS with `found: true`) and feathers from bird deaths (mobs.js).
- Plants (`PLANT` in blocks.js, e.g. wheat) are drawn as crossed quads by the mesher, aren't solid, and can drop items when broken (`game.js` `_break`).
- Characters (`characters.js`): accounts hold `characters` { id: { name, look, stats, spare, traits, created } } and `lastChar`. After `hello` the game answers `characters` (`game.characterList`); `createChar` { name, look, stats } (`createCharacter`, checked by `newCharacter`/`cleanStats`/`cleanLook`), `deleteChar` { id }, then `play` { id } joins (`game.join(uid, charId, send)`). Entries have `uid`, `charId` and `token` = "uid.charId" (the save key; backpacks are per token); account things (admin, seen) use `e.uid`; one character per Player online at a time. Names are unique across Players and characters. The look goes in `welcome.look` and `snap.players[].look` (+ `tall`); avatars.js `buildAvatar(id, material, look)` builds skin/hair/brows/clothes and the novelty heads (`headBoxes`), rebuilds when the look changes, and scales by `tallScale`. The title screen: account.js `chooseCharacter` (auto-plays `last` unless "Switch character" set the sessionStorage flag) and `openCreator` (3D preview with its own renderer). Tallness: `statEffects().reach` scales the client's REACH; `game._bonk` (Tallness over 10, `bonkChance`, cause 'bonk').
- Stats (`stats.js`) belong to the character (`player.baseStats` from the character's stats, never re-rolled; traits likewise); attribute points from levelling up (`statPointsPerLevel` per level, `player.statPoints`) are spent with the `stat` { key } message (the + on the character sheet) into `player.statBonus`, which lasts across lives. `player.stats` = `withBonus(baseStats, statBonus)`: always recompute it after changing either. Saves store `stats` (the roll), `statBonus` and `statPoints`. Use `statEffects(stats)` multipliers rather than reading raw values. The stats are mog (melee and bow damage), cracked (speed; `dodge` in `Player.damage` for attacks with cause 'mob'/'player' that aren't `blast`), bigBrain (mana), rizz (shopkeeper `priceFor` and quest `reward`; never the printer or CONSUME), builtDifferent (`hp` in `Player.maxHpNow`/`refreshMaxHp`; debuffs on players go through `game._shrugOff(e, kind)` and `_debuffTime(p, seconds)`), tallness and touchGrass (no effect yet). Saves from before the renames go through `migrateStats` (strongth, rascaliness, smartness renamed; snackitude and vibes dropped). Tests that check exact numbers should pin stats to `AVERAGE`.
- Audio: never schedule AudioParam automation every frame (it accumulates in Firefox and starves the shared audio thread); set `.value` and throttle. The context suspends when muted or the tab is hidden.
